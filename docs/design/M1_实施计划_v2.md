## 1. 两个数据集的定位

| | **QASPER v0.3** | **PubMedQA-1k** |
|---|---|---|
| 角色 | **主战场**，全部正式实验与结论 | **冒烟测试 + 泛化性附录** |
| 规模 | 1,169 篇 / 3,598 题 / 61,317 段 / 6.43M token | 1,000 题 / 约 2.5k 段 / 约 0.3M token |
| 切分 | 可做 chunk size × overlap 网格 | **固定单配置**（每篇 2–3 段，网格无意义） |
| 证据标注 | ✅ 段落级 gold evidence | ❌ 只有 yes/no/maybe + 长答案 |
| 图检索 | ✅ M3 主实验 | ❌ **明确不做**（3 段摘要上没有图可言） |
| 评测 | 段落级 recall + 答案级 | 仅答案级 |
| 完成状态 | P1–P3 已完成 | 未开始（约 1–2 小时） |

> **判断线**：若距截止不足两周且 QASPER 主结果未跑完，直接砍掉副线，不解释。

## 3. 责任边界（明确谁做什么）

### 3.1 M1 做，且只做这些

```
原始数据 → 清洗 → 段表 → 切分 → chunk 表(+元数据) → 证据对齐 → 切分实验
```

产出的**全部**内容是：`paragraphs.parquet`、`chunks.parquet`、`qa.parquet`、`manifest.json`、四份文档。

### 3.2 留给其他人做

| 任务 | 归属 | M1 提供什么 | 对方需要自行完成 |
|---|---|---|---|
| Embedding + 向量索引（BGE + FAISS） | **M2** | `chunks.parquet`（`chunk_id` / `text` / `n_tokens`） | 选模型、批量编码、建索引、持久化、增量更新 |
| 实体关系抽取 | **M3** | `chunks.parquet`（`text` / `section_path` / `para_ids`） | NER 与关系抽取、实体规范化、别名合并 |
| **参考文献抓取**（OpenAlex/S2） | **M3** | 无（**这是新增给 M3 的工作**） | 按 `paper_id`（arXiv ID）批量取 references |
| 图构建（文内结构边 / 实体共现 / 耦合 / 共被引） | **M3** | `section_idx`、`prev/next_chunk_id`、`para_ids` —— **足以建文内结构边** | 跨文档边、边权设计、图存储 |
| 图查询（1-hop / 2-hop / PPR） | **M3** | 无 | 全部 |
| 分数融合（RRF）、Cross-Encoder 重排、DOS | **M4** | `chunk_id` 作为唯一主键 | 全部 |
| 生成与提示工程（子图摘要、答案生成） | **M4 / M5** | `chunks.parquet` 的 `text` | 全部 |
| 指标定义与实现（recall / MRR / answer F1 / 分层分析） | **M5** | `qa.parquet` 的 `gold_para_ids`、`answer_type`、`writer_*` 元数据 | 指标实现、`unanswerable` 口径、多答案聚合 |
| 端到端集成与报告 | **M5** | 全部 | 全部 |

### 3.3 三个必须由 M1 把关、不能外包的点

1. **`chunk_id` 的稳定性**：一旦下游建了索引，`chunk_id` 就冻结。改一次全组返工。
2. **防泄漏**：`gold_para_ids` / `gold_chunk_ids` **只能给 M5**，绝不能进入 M2/M3/M4 的检索或建图流程。否则 recall 虚高且无法察觉。
3. **跨 config 对齐**：所有跨配置比较必须以 `para_id` 为准，`chunk_id` 只做展示。

### 3.4 需要对方先回答才能动工的（阻塞项）

| 阻塞 | 影响 M1 的哪一步 | 没有答案时的临时假设 |
|---|---|---|
| M2：embedding 模型与最大长度 | A8 的 `chunk_size` 上限 | 暂按 512（`bge-large-en-v1.5`） |
| M3：图节点粒度（chunk / paragraph） | A6 是否需要额外导出段级边字段 | 暂按 chunk |
| M4：生成时 top-k / token 预算 | A8 的 `oracle_recall@k` 取哪几个 k | 暂报 k ∈ {3,5,10} |
| M5：recall 口径、`unanswerable` 是否进分母、多答案聚合 | A4 的 `qa.parquet` 字段语义 | 暂全部保留原始标注，不做聚合 |

> 以上四条都设了临时假设，**任何一条都不会阻塞开工**。但需要在 A6 冻结 schema 之前收到确认，否则 schema 要改第二遍。

## 4. 执行顺序与关键路径

```
A1 → A2 → A3 ──┬→ A4（证据对齐）────────────────┐
               │                                  ├→ A7 → A8 → A9
               └→ A5（切分器）→ A6（chunk 表）──┘
                                                    ↑
                          B1 → B2 → B3 → B4（任意时间插入，不占关键路径）
                          C1 / C2 / C3（随 A6 一起做，不单独占时间）
```

**为什么把 A4 提前**：它只读 `paragraphs.parquet`，和切分完全解耦。提前做完，M5 立刻能开始写指标代码；而且对齐率如果低于预期，越早发现越好（当前已知残余问题只有 265 条子章节标题）。

**关键路径**：`A5 → A6 → A7 → A8`。A5 完成后 A6/A7/A8 都是短任务。

## 7. 与团队任务书的对照（2026-11-01 收到的新版）

团队任务书把 M1 描述为「加载 → 切 chunk → 另存评测文件 → 查空文本/重复/解析异常，交付 `chunks.jsonl`、`qa_dataset.jsonl`、统计报告」。**方向与本计划一致**，但有 3 处需修正、4 处缺失。

### 7.1 修正项

| # | 任务书原文 | 问题 | 采纳后的做法 |
|---|---|---|---|
| 1 | M3「如果做引用图：获取论文引用与被引用关系」 | **已实测走不通**：S2 + OpenAlex 双源、55 篇抽样、约 600 条参考文献，指向语料内的引用边为 **0** | 改用**文献耦合 / 共被引**边（25.7% 论文对相连），见 `../experiments/citation_graph_probe.md` |
| 2 | M2「实现 Top-K 检索和**基础答案生成**」+ M4「使用**同一生成模块**生成答案」 | 两处自相矛盾；两条链路生成器不同则对比不公平 | **生成模块由 M5 统一提供**，M2 只做检索；M2 不自行记录指标 |
| 3 | M1「检查是否有重复 chunk」 | overlap 造成的相邻文本重复是**设计行为**，不是缺陷，按此查会误报 | 改为查：`chunk_id` 唯一、空/空白 chunk、覆盖率 100% |

### 7.2 缺失项（前两条会让 M5 无法工作）

| # | 缺失 | 后果 | 归属 |
|---|---|---|---|
| 1 | **`para_id` 段落级坐标系** | evidence 是段落级的，没有它就反查不到「检索有没有找对地方」；且 `chunk_id` 随 size 变，跨配置不可比 | M1（A3/A6） |
| 2 | **evidence 文本 → 段落对齐**（不是「另存字符串」） | 直接搬字符串，M5 只拿到文本、算不出 recall | M1（A4） |
| 3 | **`manifest.json` 版本化**（config hash + git commit + 数据 hash） | 四人各自跑，无法确认是否同一份数据 | M1（A6） |
| 4 | **防泄漏约束**：`gold_*` 只能给 M5 | 用标注建边/调参会让 recall 虚高且无法察觉 | M1（C3） |

### 7.3 交付格式的最终约定

任务书要求 jsonl，本计划用 parquet。**两种都出**（同源双写，各一行代码）：

| 文件 | 格式 | 用途 |
|---|---|---|
| `qa_dataset.jsonl` | jsonl | 3,598 条，人可读，直接给 M5 |
| `chunks.parquet` | parquet | M2 批量编码的快路径（列裁剪） |
| `chunks.jsonl` | jsonl | 便于人工检查与跨语言读取 |
| `paragraphs.parquet` | parquet | 内部坐标系，M1 自用 |

`chunks` 表必须多带两个字段（任务书未要求，但下游必需）：`para_ids`（本 chunk 覆盖的段落列表）、`char_start/char_end`（跨 config 不变量）。
