## 2. 必须修正的三点

### 2.1 检索池没有定义 —— 这决定 C/D 两组有没有意义

四组实验的表述里，"检索方式"只写了用什么信号，**没写检索范围**。而在 QASPER 上这恰恰是决定性的：

**如果检索池限定在目标论文内部（篇内设定）：**

gold evidence **永远在目标论文里**。那么跨论文耦合边**在机制上不可能增加 recall**——它能做的只有把别的论文的 chunk 拉进候选池，而它们**全都是错的**。

→ 结论：**篇内设定下，C 组（Dense + 耦合图）必然 ≤ A 组**，不是"可能不提升"，是**结构性不可能提升**。用"C 是否优于 A"当判据，等于用一场注定输的比赛决定要不要继续。

耦合边唯一可能起作用的间接路径是二阶的：与目标论文耦合的论文，其内容可能提示目标论文里哪些 chunk 更重要——但这是很弱的信号，不该作为实验的主假设。

**如果检索池是全语料（开集设定，61,317 段 / 1,169 篇）：**

跨论文边才有意义，因为"找对论文"本身成了任务的一部分。但此时 QASPER 的 gold 只覆盖目标论文，**检索到别的论文的 chunk 一律算错**，所以指标要重新定义（见 3.1）。

### 2.2 "先 BGE 找 chunk → 耦合扩展论文 → 再回扩展论文找证据" 不是 CG-RAG 的做法

这是**两阶段流水线扩展（candidate augmentation）**，不是 CG-RAG 的**图上消息传递**。区别是实质性的：

| | 流水线扩展 | CG-RAG / LeSeGR |
|---|---|---|
| 图的作用 | 扩大候选池 | **在打分时就参与表示计算** |
| 打分函数 | 仍是 $s(q, c_i)$，图只影响"哪些 $c_i$ 进入候选" | $s(q,c_i)=f_{dense}(q, H_i)$，$H_i$ 由图消息传递得到 |
| 成本 | 低 | 高（要训练图编码器） |
| 能否解释"多跳相关性" | 不能，只是找更多候选 | 能 |

**两者都要做，但必须分开命名、分开报告**，否则会被质疑"你说的图检索到底指哪个"。

建议顺序：**先做流水线版（便宜、能快速证伪），再决定要不要上 LeSeGR 式消息传递。**

### 2.3 "只要 C 相对 A 有提升就有理由继续" —— 这个判据在篇内设定下是伪判据

理由见 2.1。正确的判据应该分设定：

- **篇内设定**：看 **B 组**（文内 chunk 图）是否优于 A。这是唯一有信息量的对照，因为 55.5% 的答案需要多段落证据。
- **开集设定**：看 **C 组**是否优于 A，此时 C 才有机制上的可能。

## 3. 两个技术风险（容易低估）

### 3.1 开集设定下 recall 的分母怎么算

QASPER 的 gold 只在目标论文内。开集检索时：

- 若按"命中的 chunk 是否属于 gold 段落"算 → 合理，但等价于"先找对论文再找对段"
- 若允许"命中任何论文的相似段落"→ 无法评分

建议：开集设定下报告两个数——**论文级 Recall@k**（top-k 里有没有目标论文）和**段落级 Recall@k**（gold 段落有没有进 top-k）。前者才是耦合边能改善的量。

### 3.2 section 内"全连接"会产生 O(n²) 边

一个 section 里有 20 个 chunk，全连接 = 190 条边；而我们最大的 section 有 627 个段落。**全连接会让图爆炸且几乎全是噪声边。**

建议内部边只用两种：
- **顺序邻接**（prev/next，可选 2 跳）
- **同 section 内的 kNN**（用 chunk 向量取 top-3，不取全连）

### 3.3 异构节点会让 PPR 的 teleport 变复杂

"节点 = 论文 + chunk" 是二分图结构。PPR 的 teleport 分布要定义在**哪个节点类型**上，直接决定结果含义：

- teleport 在 chunk 上 → 相当于在 chunk 空间做随机游走，论文节点只是中继
- teleport 在论文上 → 会偏向论文内的所有 chunk 均匀，弱化了初始检索分数

**建议：节点只用 chunk，论文归属做成边类型或特征。** 这样 PPR 语义干净，也和 CG-RAG 的 chunk-level 图同构。论文级耦合边在展开时变成"chunk → 耦合论文的 chunk"的边，和 CG-RAG 的 inter-doc 边机制一致。

## 4. 那份建议漏掉的四件事

| # | 遗漏 | 为什么重要 |
|---|---|---|
| 1 | **anchor coverage（锚点覆盖）** | 图扩展只能"放大已有命中"，**救不回首轮完全没召回的题**。如果 BGE top-10 里一个 gold chunk 都没有，扩多少邻居都没用。**这是图检索的机制上限，必须先测。** |
| 2 | **692 条不该进分母的题** | 607 题 gold 为空（100 无证据 + 174 图表证据 + 2 对齐失败 + 331 不可回答）配 85 条其他边界情况；不分流会让所有指标互相污染 |
| 3 | **`co_split_rate`** | 答案片段和它的证据是否落在同一个 chunk。比平均 recall 更能解释坏 case——证据在、答案被切走，模型必错 |
| 4 | **候选预算爆炸** | top-10 chunk → 其所属论文的耦合邻居（平均每篇几十篇）→ 每篇再取 top-m chunk，不设预算会从 10 个候选涨到几千个，检索延迟和噪声同时爆掉 |

## 5. 建议的实验矩阵（在四组基础上补两个维度）

| 组 | 检索池 | 信号 | 回答什么问题 |
|---|---|---|---|
| A | 篇内 | Dense | 基线 |
| A′ | **开集** | Dense | 开集基线（**耦合边的对照组必须是这个**） |
| B | 篇内 | Dense + 文内 chunk 图 | 局部结构是否有用 |
| C | **开集** | Dense + 耦合图 | 跨论文关系是否有用 |
| D | 开集 | Dense + 两种图 | 组合能否叠加 |

**关键改动：A′ 是新增的，而且必须存在。** 没有 A′，C 的提升无法归因——你不知道是耦合边有用，还是仅仅因为"从篇内换到开集"这个设置本身改变了难度。

指标（每组都报）：
1. **论文级 Recall@k**（开集才有）
2. **段落级 Recall@k**（分母 = 2,991）
3. **anchor coverage**（top-k 里至少有一个 gold 的题目占比）—— 图检索的机制上限
4. `co_split_rate`
5. 候选预算（平均候选数 / 延迟）

## 6. 我建议的执行顺序

```
A5 chunk 表（M1） → M2 Dense 基线（A 组）
                  → 全量耦合图统计（M3，约 3–5 分钟，OpenAlex）
                  → 1-hop 流水线扩展（C 组，先不做图编码器）
                  → 判据：C vs A′ 的论文级 Recall 是否提升
                  → 提升才上 LeSeGR 式消息传递；不提升就写负结果
```

**M1 现在能独立做的**：A5 + A8 的 oracle 上界（每个 gold 段落在给定切分下是否可达）。这个上界不依赖任何人，而且能提前回答"切分本身是否已经吃掉了结构信息"——如果 oracle recall 已经接近 100%，那图检索的空间就很有限。

---

## 7. 一句话结论

> 那份建议的**方向对、四组实验的骨架对、最关键的那句"问题围绕指定论文"也对**；但它没有定义检索池，而检索池决定了 C/D 两组是"有意义的实验"还是"注定为负的对照"。**先定检索池，再定判据，最后才是建图。**
