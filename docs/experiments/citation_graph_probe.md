# 引文图可行性探测（为 M3 铺路）

> 日期：2026-11-01　|　脚本：`scripts/dev/probe_citation_graph.py`（Semantic Scholar）、`scripts/dev/probe_openalex_graph.py`（OpenAlex）
> 目的：QASPER 本身不含参考文献，要判断「能否给 QASPER 补一张引文图，让 M3 的图检索成立」。

---

## 1. 探测设计与结果

QASPER 的 `paper_id` 就是 arXiv ID（如 `1912.01214`），所以可以按 ID 去外部库取参考文献。两个数据源各测一次。

### 1.1 Semantic Scholar Graph API（30 篇抽样）

| 指标 | 结果 |
|---|---|
| 请求成功 | **6 / 30**（其余 24 次全部 HTTP 429 限流） |
| 参考文献总数 | 173 |
| 其中能解析出 arXiv ID 的 | 60（**34.7%**） |
| **指向本语料（1,169 篇内）的引用** | **0（0.0%）** |
| 有 ≥1 条语料内引用的论文 | 0 / 6 |
| 文献耦合对（共享参考文献的论文对） | **3 / 15（20.0%）**，平均共享 2.3 篇 |

### 1.2 OpenAlex（25 篇抽样，无 API key）

| 指标 | 结果 |
|---|---|
| 请求成功 | **25 / 25（无限流）** |
| 平均参考文献数 | **24.0 / 篇** |
| **指向抽样集合内的引用边** | **0** |
| 有语料内引用的论文 | 0 / 25 |
| 文献耦合对 | **77 / 300（25.7%）**，平均共享 1.4 篇 |

---

## 2. 结论（这一节决定 M3 的方案）

### 2.1 直接引文边 = 0，照 CG-RAG 的图结构做不出来

两个独立数据源、55 篇抽样、合计约 600 条参考文献，**没有任何一条引用落在 QASPER 语料内部**。

原因不难理解：QASPER 的 1,169 篇是「带问答标注的 NLP 论文」这一人工筛选子集，不是围绕某个主题的引文簇；而一篇 2019 年的论文引用的是 2015–2018 年的工作，那些论文大多不在这个子集里。

→ **CG-RAG 里"跨文档引用边"这一层，在 QASPER 上做不出可用的密度。** 任何"复现 CG-RAG 图结构"的承诺在这一项上都是空的。

### 2.2 文献耦合边 = 25.7%，这才是可行路径

**文献耦合（bibliographic coupling，Kessler 1963）**：两篇论文若共享至少一篇参考文献，则连一条边，权重 = 共享篇数。

这个度量**不要求被引论文在我们的语料内**，所以不受 2.1 的限制。实测 25 篇随机样本里 300 个论文对有 77 对相连（25.7%）。按这个比例外推到 1,169 篇：

$$
\frac{1169 \times 1168}{2} \approx 682{,}000 \text{ 对} \times 25.7\% \approx 175{,}000 \text{ 条边}
$$

**这是一个稠密、可用、且语义明确的图**——「引用同一批工作的论文，在研究脉络上相关」。

补充：还有它的对偶度量**共被引（co-citation，Small 1973）**「被同一批后续工作引用」，同样只需要参考文献表，可以一并产出。

### 2.3 数据源选型

**用 OpenAlex，不用 Semantic Scholar。** S2 在 1.1 秒间隔下仍有 80% 请求被 429，且只有 34.7% 的参考文献能解析出 arXiv ID；OpenAlex 25/25 成功、无需 key、平均 24 条参考文献。

### 2.4 用「文献耦合」替换「引用边」，符合 CG-RAG 的思路吗？

**架构上完全兼容，语义上不等价。** 分开说：

**兼容的部分（可以直接套用 LeSeGR，代码不用改）**

CG-RAG 的 LeSeGR 只用两件事：邻居集合 $\mathcal{N}(i)$，以及两条门控信号——

$$\delta_{qj}=f_{sparse}(q,c_j),\qquad \alpha_{ij}=\mathrm{MLP}(c_i^{dense}\ominus c_j^{dense})$$

这两个都**不依赖边的语义**：$\delta$ 只看"邻居和查询词面像不像"，$\alpha$ 只看"邻居和中心 chunk 语义差多少"。所以换成什么边，消息传递的公式原封不动。

**一个具体的技术映射**：CG-RAG 的跨文档边定义在 **chunk 级**——论文 $v$ 的 chunk 连到被它引用的论文 $u$ 里 Top-$n$ 相关的 chunk。耦合边天然是 **paper 级**，所以要做同样的展开：给定论文 $A$ 与耦合论文 $B$，把 $A$ 的 chunk 连到 $B$ 的 Top-$n$ 相关 chunk。**机制同构，只是"触发条件"从"谁引用谁"换成了"谁和谁引了同一批工作"。**

**不等价的部分（必须在报告里讲清楚）**

| | CG-RAG 的引用边 | 我们的耦合边 |
|---|---|---|
| 方向 | **有向**（$v \to u$，新的引用旧的） | **无向**（对称） |
| 语义 | 知识流向、权威性、时间先后 | 主题同源、同一学术脉络 |
| CG-RAG 的原始动机 | "一篇论文可能因为被多篇相关论文引用而相关，哪怕它自己不含关键词" | 不适用：耦合编码的是"共同的知识基础"，不是"被引用带来的相关性" |
| 噪声性质 | 引用动机噪声（礼节性引用、对比性引用） | 同期同领域但不相干的论文也会耦合 |

**结论**：这是一次**"图的替代实例化"（alternative instantiation），不是复现**。

- ✅ 可以说：在同一套 LeSeGR 框架下，把跨文档边换成耦合边，方法链路完整成立。
- ❌ 不能说：我们复现了 CG-RAG；也不能把我们的数字和论文 Table 3 的数字并排比较。
- ⚠️ 必须在报告里显式说明：**我们测的是"结构信息是否有用"，不是"引文结构是否有用"**。这两句话差别很大，评审会问。

## 3. M3 的图应该怎么设计（基于以上实测）

原来设想照抄 CG-RAG 的三层边（文内 + 跨文档引用 + 图编码），实际要改成：

| 层 | 边类型 | 来源 | 是否可行 | 说明 |
|---|---|---|---|---|
| L1 | **文档内结构边**：section → paragraph 层级、chunk 的 prev/next | P3/P5 已产出 | ✅ 直接可用 | 覆盖 1,169 篇 / 61,317 段 |
| L2 | **文献耦合边**（+ 可选共被引） | OpenAlex `referenced_works` | ✅ **实测 25.7% 论文对相连** | 跨文档边的**主力**，替代 CG-RAG 的引用边 |
| L3 | **实体共现边** | NER（SciSpacy / spaCy）跑全文 | ✅ 无需外部数据 | NLP 论文共享 BERT / Transformer / GLUE 等实体，跨文档天然连通 |
| L4 | **语义 kNN 边** | 复用 M2 的 embedding 做 kNN | ✅ M2 完成即得 | CG-RAG 的 future work 里就叫 "implicit semantic links" |
| L5 | ~~直接引文边~~ | Semantic Scholar / OpenAlex | ❌ **实测为 0** | 不要做，做了也是空图 |

**这个替换是必须向组里说明的**：M3 做出来的图和论文里的图**语义不同**。论文的图是"谁引用了谁"（有方向的、时间上单向的），我们的是"谁和谁引了同一批工作"（无方向的、同期相关）。1-hop / 2-hop / PPR 的算法完全可复用，但**解释边的时候必须说实话**。

## 4. M1 需要新增的交付物

| # | 交付物 | 内容 | 依赖 |
|---|---|---|---|
| N1 | `scripts/02_fetch_references.py` | 1,169 篇 × OpenAlex → `data/processed/references.parquet`（`paper_id, openalex_id, referenced_works[]`）。按 0.12s 间隔约 3–5 分钟 | 无 |
| N2 | `scripts/03_build_edges.py` | 产出 `data/processed/edges.parquet`：`src_id, dst_id, edge_type ∈ {intra_section, adjacency, coupling, cocitation}, weight` | N1 + P5 |
| N3 | 边表 schema 文档 | 写进 `data_contract.md`，给 M3 直接用 | N2 |
| N4 | **防泄漏校验** | 断言：图里不含任何由 `gold evidence` 派生的边（否则等于把答案喂进检索） | N2 |

> N4 是硬要求。**任何用 gold evidence 建的边，都会让 recall 虚高**，这是这类实验最常见的作弊点。
